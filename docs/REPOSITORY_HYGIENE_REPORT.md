# Repository Hygiene Report — spl-tls-analyze v0.1.0b0

**Date:** 2026-06-03
**Base:** Findings from Phase 17B Artifact Integrity Audit
**Scope:** Resolve all artifact-level integrity issues without adding features.

## Changes Applied

### 1. Deprecated `spl_v7_project/` (Slim Variant)

**Issue:** The slim variant at `/spl_v7_project/` was missing 4 of 7 declared Python packages (`scripts/`, `spl_v7/`, `tls_policy_adapter/`, `weakness_mapper/`), the entire test suite, and all script files. It could not build, install, or run.

**Action:** Added `_DEPRECATED.txt` marker file at `spl_v7_project/_DEPRECATED.txt` with explanation of what's missing and where to find the complete variant.

**Status:** ✅ Deprecated (not deleted — preserves git history)

---

### 2. Fixed `docker-test` Workflow

**Issue:** `make docker-test` always failed because:
- `tests/` directory was not copied into the Docker image
- `pytest` was not installed (Dockerfile does `pip install .` without `[dev]` extras)
- `spl-core` dependencies not installed (`pip install .` without `[spl-core]` extras)

**Actions:**

**`Makefile`** — Replaced the broken `docker-test` target with a helpful message directing users to run tests natively:

```makefile
docker-test:
    @echo "NOTE: Tests are not included in the Docker image (pytest not installed, tests/ not copied)."
    @echo "Run tests natively instead:  make test"
    @echo "Or install with dev extras:   pip install \".[dev]\" && python -m pytest tests/ -v"
    @exit 1
```

**`docs/DOCKER_USAGE.md`** — Replaced the "Run Release Verification Inside Docker" section with native test instructions.

**Status:** ✅ Fixed (docker-test now provides guidance instead of failing silently)

---

### 3. Resolved `requirements.txt` Duplication

**Issue:** `requirements.txt` duplicated the dependency declarations from `pyproject.toml`'s `[project.optional-dependencies] spl-core` section, but was not referenced by any build tool or script.

**Action:** Added a comment header explaining:
- The file is informational only
- Dependencies are managed in `pyproject.toml`
- How to install each optional extra set: `.[spl-core]`, `.[dev]`, `.[kafka]`
- Where to find the authoritative list

**Status:** ✅ Fixed (requirements.txt retained as documentation with clear provenance)

---

### 4. Moved Generated Artifacts Out of Repository Root

**Issue:** Three generated artifacts were sitting in the project root:
- `dashboard.html` (51 KB) — generated by `examples/demo.py`
- `v71_graph_snapshot.json` (144 KB) — generated by `examples/demo.py`
- `capability_report.json` (10 KB) — generated by `scripts/run_weakness_mapper.py`

These are runtime outputs, not source code. They clutter the root and are large.

**Action:** Moved all three to `reports/generated/`:
- `reports/generated/dashboard.html`
- `reports/generated/v71_graph_snapshot.json`
- `reports/generated/capability_report.json`

**Status:** ✅ Moved

---

### 5. Updated `.gitignore`

**Issue:** `.gitignore` only ignored `dashboard.html` and the `reports/local_real_validation/` subdirectory. Generated artifacts could be accidentally tracked.

**Action:** Added gitignore entries for:
- `v71_graph_snapshot.json` — generated artifact
- `capability_report.json` — generated artifact
- `reports/generated/` — entire generated artifacts directory

Reorganized the `.gitignore` sections for clarity.

**Status:** ✅ Updated
